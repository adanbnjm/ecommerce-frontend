Abarrotes Verde

Mi parte fue crear useDebounce y useApi, siguiendo lo que vimos con la hermana Belén. Los entregué desde feat/custom-hooks en el PR #1, que el equipo ya integró a main.

1. useDebounce

Espera 3 segundos después de la última escritura. Cada cambio cancela el timeout anterior. El input responde inmediatamente, pero la lista usa el texto con pausa para filtrar.

const texto = useDebounce(query, 3000);

2. useApi

Recibe una función que devuelve una promesa con los datos. Devuelve data, cargando, error y recargar. Maneja éxito, error y finalización con then, catch y finally.

El contador permite repetir la consulta. La variable cancelado evita actualizar el estado con respuestas anteriores después de una recarga o del desmontaje. No detiene físicamente la petición.

3. Cómo conectarlos

  • La interfaz filtra los productos con el valor que devuelve useDebounce.
  • El servicio que recibe useApi debe devolver los datos, por ejemplo respuesta.data.
  • La interfaz muestra la carga, el error y un botón para recargar.
  • Después de crear, editar o eliminar, se llama a recargar().

Esta versión de clase consulta al montar y al recargar; cambiar filtros no hace una nueva consulta automáticamente.

4. Avance del equipo

La versión integrada incluye tienda, navegación, catálogo, categorías, carrito y layout de administración. Para preparar la publicación incorporé esos cambios a mi rama, sin modificar main.

Conecté useDebounce al buscador del catálogo y corregí el mensaje al agregar al carrito para resolver el error de TypeScript. La configuración de Pages usa una ruta base y navegación con hash.

El catálogo usa datos locales de ejemplo. El login y otras secciones están pendientes. useApi está disponible, pero todavía no está conectado al catálogo.

5. Publicación y comprobaciones

El workflow de GitHub Actions compila la web desde mi rama y guarda un artefacto descargable con la web y el reporte. El despliegue se ejecuta cuando el propietario activa GitHub Pages con origen GitHub Actions.

Mi cuenta puede subir código, pero no administrar Pages. La URL pública solo estará lista después de que termine el job de despliegue. TypeScript se revisa con npx tsc -b y el build completo se comprueba en Actions sobre Linux.
